Kubernetes 学习路径

概览

Kubernetes（简称 K8s）是开源的容器编排系统，用于自动化部署、扩展和管理容器化应用。由 CNCF（Cloud Native Computing Foundation）托管，当前稳定版本为 v1.33。

本学习路径按照渐进式五个级别组织，从概念理解到实际操作，帮助你系统掌握 Kubernetes。

如何使用本学习路径

  1. 按顺序学习：从 Level 1 到 Level 5，每个级别都建立在前一个的基础之上
  2. 动手实践：每个代码示例都在 code-examples/ 目录中，请实际运行
  3. 查阅资源：resources.md 收录了所有官方文档和社区资源的链接
  4. 主线学习：learning-path.md 是核心学习指南，按级别逐步深入

Kubernetes 学习路径

Level 1: 概览与动机

目标：理解 Kubernetes 是什么以及为什么需要它

1.1 Kubernetes 解决什么问题

在容器化时代，单个容器很容易管理，但生产环境中你面临以下挑战： - 容器挂了需要自动重启 - 需要按需自动扩缩容 - 多个容器之间需要负载均衡和服务发现 - 需要滚动更新和回滚 - 需要管理配置和密钥

Kubernetes 就是解决这些问题的容器编排系统——它自动管理容器化应用的全生命周期。

1.2 部署演进历史

时代 方式 问题
传统部署 应用直接跑在物理服务器上 无资源隔离，扩展困难
虚拟化部署 每个应用跑在 VM 中 VM 太重（每个包含完整 OS）
容器部署 应用跑在容器中 轻量、可移植、但数量多了需要编排

1.3 Kubernetes 的核心能力

  • 服务发现与负载均衡：通过 DNS/IP 暴露容器，自动负载均衡
  • 存储编排：自动挂载本地、云等多种存储系统
  • 自动滚动发布与回滚：以受控速率管理期望状态
  • 自动装箱：根据 CPU/内存需求将容器调度到合适节点
  • 自愈：重启/替换故障容器，就绪前不对外服务
  • 密钥与配置管理：无需重建镜像即可管理敏感信息
  • 水平扩展：通过命令、UI 或自动扩缩实现

1.4 谁在使用 Kubernetes

Spotify（1600+ 服务）、Airbnb、Netflix（每日数百 TB 数据）、Pinterest、Uber 等大型互联网公司，以及大量中小企业。K8s 在生产环境采用率约 82%。

1.5 何时不应使用 Kubernetes

  • 你的应用是单体应用且无容器化计划
  • 团队规模很小（<5 人），运维 K8s 的成本可能超过收益
  • 仅需运行少量容器，Docker Compose 就够了
  • 不需要高可用、自动扩缩等高级功能
  • 团队没有容器和 Linux 网络基础

1.6 Kubernetes vs 替代方案

维度 Kubernetes Docker Swarm Nomad
复杂度 高 低 低-中
功能丰富度 非常丰富 基础 中等
生态系统 庞大（Helm, Istio, ArgoCD 等） 小 HashiCorp 生态
适合规模 大规模 小规模 中等规模
支持非容器工作负载 否 否 是（VM, 批处理等）

Level 3: 核心概念

目标：建立 Kubernetes 的心智模型

3.1 Pod — 最小部署单元

Pod 是 Kubernetes 中最小的可部署单元，包含一个或多个容器。同一 Pod 内的容器共享网络和存储。

# 一个简单的 Pod
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
  labels:
    app: nginx
spec:
  containers:
  - name: nginx
    image: nginx:1.25
    ports:
    - containerPort: 80
    resources:
      requests:
        memory: "64Mi"
        cpu: "250m"
      limits:
        memory: "128Mi"
        cpu: "500m"

要点： - Pod 是临时的（ephemeral），销毁后不会重建 - 同一 Pod 内容器共享 IP 和端口空间，通过 localhost 通信 - 通常不直接创建 Pod，而是通过 Deployment 等控制器管理

常见错误： - 直接创建裸 Pod → Pod 挂了不会自动重启 - 未设置 resource requests/limits → 可能导致资源争抢

3.2 Deployment — 声明式管理 Pod 副本

Deployment 管理一组 Pod 副本，提供滚动更新、回滚和扩缩容能力。

apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
  labels:
    app: nginx
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.25
        ports:
        - containerPort: 80

关键操作：

# 创建
kubectl apply -f deployment.yaml

# 扩缩容
kubectl scale deployment nginx-deployment --replicas=5

# 滚动更新
kubectl set image deployment/nginx-deployment nginx=nginx:1.26

# 查看更新状态
kubectl rollout status deployment/nginx-deployment

# 回滚
kubectl rollout undo deployment/nginx-deployment

# 查看历史
kubectl rollout history deployment/nginx-deployment

常见错误： - 创建后修改 selector → selector 不可变，需要重建 - 使用 :latest 标签 → 滚动更新可能无法检测到变化

3.3 Service — 稳定的网络端点

由于 Pod IP 是临时且会变化的，Service 提供了一个稳定的网络端点和负载均衡。

apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  selector:
    app: nginx
  ports:
  - protocol: TCP
    port: 80
    targetPort: 80
  type: ClusterIP  # 默认，集群内部访问

Service 类型：

类型 说明 典型场景
ClusterIP 集群内部 IP（默认） 内部服务间通信
NodePort 在每个节点开放端口 (30000-32767) 开发/测试
LoadBalancer 云厂商提供负载均衡器 生产对外暴露
ExternalName DNS CNAME 重定向 外部服务引用

常见错误： - selector 与 Pod label 不匹配 → Service 找不到后端 Pod - NodePort 端口冲突 → 默认范围 30000-32767，可能与其他服务冲突

3.4 ConfigMap 与 Secret — 配置管理

ConfigMap 存储非敏感配置，Secret 存储敏感数据（密码、密钥等）。

# ConfigMap
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  APP_ENV: "production"
  LOG_LEVEL: "info"
  config.yaml: |
    database:
      host: db.example.com
      port: 5432
---
# Secret (base64 编码)
apiVersion: v1
kind: Secret
metadata:
  name: db-secret
type: Opaque
data:
  password: cGFzc3dvcmQxMjM=  # echo -n 'password123' | base64
---
# 在 Pod 中使用
apiVersion: v1
kind: Pod
metadata:
  name: app-pod
spec:
  containers:
  - name: app
    image: myapp:1.0
    envFrom:
    - configMapRef:
        name: app-config
    env:
    - name: DB_PASSWORD
      valueFrom:
        secretKeyRef:
          name: db-secret
          key: password
    volumeMounts:
    - name: config-volume
      mountPath: /etc/config
  volumes:
  - name: config-volume
    configMap:
      name: app-config

常见错误： - Secret 数据未 base64 编码 → 创建失败 - 更新 ConfigMap 后 Pod 未重启 → 需要重启 Pod 或使用热更新机制

3.5 Namespace — 资源隔离

Namespace 提供集群内资源隔离机制，适合多团队/多环境共享同一集群。

# 创建 namespace
kubectl create namespace dev

# 在特定 namespace 中操作
kubectl apply -f deployment.yaml -n dev

# 查看所有 namespace
kubectl get namespaces

# 设置默认 namespace
kubectl config set-context --current --namespace=dev

常见错误： - 跨 namespace 引用 Service → 需要使用 service-name.namespace.svc.cluster.local - ResourceQuota 未设置 → 某个 namespace 可能耗尽集群资源

3.6 概念关系图

Namespace (隔离环境)
  └── Deployment (管理 Pod 副本，声明式)
        └── ReplicaSet (维护副本数)
              └── Pod (最小部署单元，含容器)
                    └── Container (实际应用)
  └── Service (稳定网络端点 → 负载均衡到 Pod)
  └── ConfigMap/Secret (配置注入到 Pod)
  └── PersistentVolume/PVC (持久化存储)
  └── Ingress (HTTP 路由到 Service)

步骤 3：添加配置和健康检查

# 03-patterns/01-web-app-full.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-app
  labels:
    app: web
spec:
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: nginx
        image: nginx:1.25
        ports:
        - containerPort: 80
        resources:
          requests:
            memory: "128Mi"
            cpu: "250m"
          limits:
            memory: "256Mi"
            cpu: "500m"
        livenessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 10
          periodSeconds: 5
        readinessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 5
          periodSeconds: 5
        env:
        - name: APP_ENV
          valueFrom:
            configMapKeyRef:
              name: web-config
              key: APP_ENV
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: web-config
data:
  APP_ENV: "production"
  LOG_LEVEL: "info"
---
apiVersion: v1
kind: Service
metadata:
  name: web-app-service
spec:
  selector:
    app: web
  ports:
  - protocol: TCP
    port: 80
    targetPort: 80
  type: NodePort

4.2 模式二：部署有状态应用（MySQL StatefulSet）

# 03-patterns/02-stateful-app.yaml
apiVersion: v1
kind: Service
metadata:
  name: mysql-headless
spec:
  selector:
    app: mysql
  ports:
  - port: 3306
    name: mysql
  clusterIP: None  # Headless Service，StatefulSet 必需
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mysql
spec:
  serviceName: mysql-headless
  replicas: 1
  selector:
    matchLabels:
      app: mysql
  template:
    metadata:
      labels:
        app: mysql
    spec:
      containers:
      - name: mysql
        image: mysql:8.0
        env:
        - name: MYSQL_ROOT_PASSWORD
          valueFrom:
            secretKeyRef:
              name: mysql-secret
              key: root-password
        ports:
        - containerPort: 3306
        volumeMounts:
        - name: mysql-data
          mountPath: /var/lib/mysql
  volumeClaimTemplates:  # StatefulSet 特有：自动创建 PVC
  - metadata:
      name: mysql-data
    spec:
      accessModes: ["ReadWriteOnce"]
      resources:
        requests:
          storage: 5Gi
---
apiVersion: v1
kind: Secret
metadata:
  name: mysql-secret
type: Opaque
data:
  root-password: bXlzcWxyb290MTIz  # echo -n 'mysqlroot123' | base64

  name: data-cleanup

  schedule: "0 2 * * *"  # 每天凌晨 2 点

    spec:
      template:

4.4 模式四：Ingress HTTP 路由

# 03-patterns/04-ingress.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: web-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  rules:
  - host: app.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: web-app-service
            port:
              number: 80
      - path: /api
        pathType: Prefix
        backend:
          service:
            name: api-service
            port:
              number: 8080

注意：使用 Ingress 前需要先安装 Ingress Controller，minikube 中可运行 minikube addons enable ingress

4.5 常见生产实践

实践 说明
始终设置 resources 防止资源争抢，Pod 被 OOMKilled
始终设置健康检查 livenessProbe + readinessProbe
不要使用 :latest 标签 避免不可预测的镜像版本变化
使用 Namespace 隔离 dev/staging/prod 分离
配置 NetworkPolicy 默认拒绝，显式允许
设置 PodDisruptionBudget 维护期间保证最小可用副本数
配置 HPA 自动扩缩 根据负载自动调整副本数
Secret 加密存储 启用 EncryptionConfiguration

5.3 架构深入理解

了解 K8s 内部架构有助于高级运维和故障排查：

控制平面组件： - kube-apiserver：所有操作的入口，REST API 前端 - etcd：分布式键值存储，集群状态的唯一真实来源 - kube-scheduler：将 Pod 调度到合适的节点 - kube-controller-manager：运行所有控制器（部署、副本、节点等） - cloud-controller-manager：云厂商特定的控制循环

节点组件： - kubelet：每个节点上的代理，管理 Pod 生命周期 - kube-proxy：维护网络规则，实现 Service 负载均衡

数据流：

用户 → kubectl → kube-apiserver → 验证 → 写入 etcd
  → controller-manager 监听 → 创建 Pod
  → scheduler 调度 → 分配到节点
  → kubelet 监听 → 调用 CRI 启动容器
  → kube-proxy 配置网络规则

5.5 实战练习项目

# Level 3 - 核心概念示例：Service
# Service 为一组 Pod 提供稳定的网络端点和负载均衡
#
# 使用方法（先确保 deployment.yaml 中的 Pod 已运行）：
#   kubectl apply -f service.yaml
#   kubectl get services
#   # 在 minikube 中访问
#   minikube service nginx-service
#   # 或端口转发

#   # 清理
#   kubectl delete -f service.yaml

apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  selector:
    app: nginx  # 匹配 Pod 的 label
  ports:
  - protocol: TCP
    port: 80         # Service 端口
    targetPort: 80   # Pod 容器端口
  type: NodePort     # 在每个节点开放端口 (30000-32767)

              echo "=== Cleanup completed at $(date) ==="

# Level 4 - 实践模式：Ingress HTTP 路由
# 通过域名和路径将外部流量路由到不同 Service
#
# 前置条件（minikube）：
#   minikube addons enable ingress
#
# 使用方法：
#   kubectl apply -f ingress.yaml
#   kubectl get ingress
#   # 在 minikube 中获取 Ingress 地址
#   minikube ip
#   # 将域名解析到该 IP（或添加 /etc/hosts）
#   # echo "$(minikube ip) app.example.com" | sudo tee -a /etc/hosts
#   # 访问
#   curl http://app.example.com/
#   curl http://app.example.com/api
#   # 清理
#   kubectl delete -f ingress.yaml

---
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: web-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  rules:
  - host: app.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: web-app-service  # 需要先部署 web-app
            port:
              number: 80
      - path: /api
        pathType: Prefix
        backend:
          service:
            name: api-service  # 需要先部署 api-service
            port:
              number: 8080

# Level 4 - 实践模式：有状态应用（MySQL StatefulSet）
# 包含：Headless Service + StatefulSet + PVC + Secret
#
# 使用方法：
#   kubectl apply -f stateful-app.yaml
#   kubectl get statefulsets,pods,pvc,services
#   # 连接 MySQL
#   kubectl run mysql-client --image=mysql:8.0 --rm -it -- \
#     mysql -h mysql-0.mysql -uroot -p
#   # 清理（注意 PVC 不会自动删除）
#   kubectl delete -f stateful-app.yaml
#   kubectl delete pvc -l app=mysql

---
apiVersion: v1
kind: Secret
metadata:
  name: mysql-secret
type: Opaque
data:
  # echo -n 'mysqlroot123' | base64
  root-password: bXlzcWxyb290MTIz

---
apiVersion: v1
kind: Service
metadata:
  name: mysql-headless
spec:
  selector:
    app: mysql
  ports:
  - port: 3306
    name: mysql
  clusterIP: None  # Headless Service，StatefulSet 必需
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mysql
spec:
  serviceName: mysql-headless
  replicas: 1
  selector:
    matchLabels:
      app: mysql
  template:
    metadata:
      labels:
        app: mysql
    spec:
      containers:
      - name: mysql
        image: mysql:8.0
        env:
        - name: MYSQL_ROOT_PASSWORD
          valueFrom:
            secretKeyRef:
              name: mysql-secret
              key: root-password
        ports:
        - containerPort: 3306
        volumeMounts:
        - name: mysql-data
          mountPath: /var/lib/mysql
  volumeClaimTemplates:
  - metadata:
      name: mysql-data
    spec:
      accessModes: ["ReadWriteOnce"]
      resources:
        requests:
          storage: 5Gi

# 使用方法：
#   kubectl apply -f web-app-full.yaml

apiVersion: v1
kind: ConfigMap

  name: web-config
data:
  APP_ENV: "production"
  LOG_LEVEL: "info"

apiVersion: v1
kind: Secret
metadata:
  name: web-secret
type: Opaque
data:
  # echo -n 'admin123' | base64

---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-app
  labels:
    app: web
spec:
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: nginx
        image: nginx:1.25
        ports:
        - containerPort: 80
        resources:
          requests:
            memory: "128Mi"
            cpu: "250m"
          limits:
            memory: "256Mi"
            cpu: "500m"
        livenessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 10
          periodSeconds: 5
        readinessProbe:
          httpGet:
            path: /
            port: 80
          initialDelaySeconds: 5
          periodSeconds: 5
        envFrom:
        - configMapRef:
            name: web-config
        env:
        - name: ADMIN_PASSWORD
          valueFrom:
            secretKeyRef:
              name: web-secret
              key: admin-password

---
apiVersion: v1
kind: Service
metadata:
  name: web-app-service
spec:
  selector:
    app: web
  ports:
  - protocol: TCP
    port: 80
    targetPort: 80
  type: NodePort
